## 全局唤起与原生窗口

- 新增随 DSH Host 启动的 macOS 原生 Friday 面板；焦点在其他应用时也可通过默认 `Option+Space` 唤起或收起。
- 沿用插件设置页的自定义快捷键，保存后立即重新注册；系统冲突会在设置页显示错误。
- 原生面板可在屏幕上任意拖动，并在本次进程内保留移动后的位置；DSH 内浮层标题栏也支持拖动。
- macOS 26 使用 `NSGlassEffectView`，旧系统使用 `NSVisualEffectView`；Web 浮层提高透明度并加入背景模糊。
- 全局能力依赖 DSH Host 正在运行，不是脱离 DSH 的独立常驻产品。

## 快捷输入区

- 中文 placeholder 改为灰色的「向 Friday 提问」，不含省略号。
- 左侧加号仅添加图片，中间输入，右侧发送/停止；沿用 Enter 发送和 Shift+Enter 换行。
- 加号和发送按钮统一尺寸、图标、间距与垂直对齐。
- 输入组件由快捷浮层和 Inbox 共用，减少交互分叉。

## Inbox 当前页续聊

- 选中对话后，消息下方直接出现固定输入框；流式回答、引用、停止和图片均在当前详情页完成。
- 移除打开快捷浮层的「继续问答」按钮，不再为续聊弹出另一层窗口。
- 「升级为正式任务」按钮简化为「升级」；压缩、工作区选择、任务创建和归档流程未改变。

## 数据与安全边界

- 原生窗口通过本地 WebKit 桥接复用 Friday Host，不另起未认证 HTTP 服务，不另存聊天正文。
- 仍使用原生 `friday-*` Session、Attachments、Web Search-only 工具策略、压缩升级与归档逻辑。
- DSH Slot Client 继续使用宿主共享 React；独立原生页面使用自己的自包含构建。
- 修正配置重复加载：只有快捷键实际变化时才发送配置变更通知。

## 验证

- 44/44 自动化测试通过，Swift 原生程序和两套 Web 产物构建成功。
- 原生实测：全局唤起/收起成功，窗口坐标按拖动量变化，React 客户端就绪，热键无注册冲突。
- 真实窗口 OCR 确认「向 Friday 提问」等可见文案；未以静态稿代替运行窗口。
- 0.2.0 安装 `application: applied`，Host fiber active，四个 DSH Slot 均 active，API 401/403 拒绝路径保持。
- 已认证浏览器视觉、Inbox 点击操作和真实模型端到端仍未自动验证，详见 [0.2.0 测试报告](07-test-report-0.2.0.md)。
