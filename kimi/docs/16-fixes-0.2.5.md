## 清空与过期清理

### 根因

- 升级在“正式任务已创建、源会话尚未归档”阶段中断时，索引可能已有 `upgradedSessionId`，却没有 `archivedAt`。
- 原列表只按 `archivedAt` 判断活动状态，导致这种会话继续进入 `clear()` / `cleanup()`；`archive()` 又明确拒绝删除已升级会话，于是整个清理请求报错。

### 修复

- 活动列表同时排除 `archived` 和 `upgraded`；归档视图接受任一状态。
- 不删除或清空 `upgradedSessionId`、`upgradeSummary` 等恢复信息，也不把升级中的会话误作普通过期会话。
- `tests/cleanup.test.js` 用真实状态组合复现：过期普通会话被清理，升级中断会话不参与 clear/cleanup，恢复摘要保留。

## 设置页参数

- 原 `publicConfig()` 在返回配置前等待 `repository.list()`；任一历史列表错误都会使整个 `/config` 失败，SettingsForm 随后只显示错误，不显示任何参数。
- 现在最近会话读取失败仅降级 `recent: null` 并记录日志，不影响默认模型、视觉模型、快捷键、保留期、模型目录和原生状态返回。
- Client 额外提供配置加载失败时的默认表单值，保存仍调用既有受认证配置 API；输入校验继续使用 `normalizeConfig()`。

## 升级流程

### 旧行为

- 点击升级后立即在 Host 压缩，用户无法查看或修改摘要。
- `sessionController.prompt()` 将摘要作为正式输入提交并唤醒 Agent，因此新任务会立即执行，而不是等待用户。

### 新行为

1. 点击“升级”后并行调用 `POST /upgrade/preview` 与 `/workspaces`；预览只生成摘要，不创建任务。
2. 对话框上方显示可编辑的压缩上下文；下方选择工作区。名称使用主文本颜色，路径单独使用次级灰色，不再把路径塞进醒目选项文本。
3. 用户点击“压缩并新建”后，将**编辑后的**摘要与工作区一起提交；不在确认时重复压缩。
4. Host 创建普通 `task-*` Session，使用 `sessionController.resolveAgent()` 取得原生 Agent，再调用 `Agent.inject()` 写入完整的用户上下文消息。
5. DSH Agent Loop 源码明确：`inject()` 调用 `send(input, 'next-step', false)`，只持久化下一步上下文，不唤醒 Agent；`followup()` 才是 `send(..., true)`。
6. 注入后 flush 原生 Session，归档 Friday 源会话并打开正式对话。任务等待用户下一条指令，不自动调用模型或工具。

### 中断恢复

- `created`：已有任务 ID 与摘要但尚未确认注入；重试只在原任务注入，不重复创建。
- `injected`：上下文已写入；若源归档失败，重试只完成归档，不重复注入。
- 通过事件内容查重保证恢复不会重复插入同一摘要；旧的 `submitted` 记录仍可读取，不强制迁移历史日志。
