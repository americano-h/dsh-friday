# Inbox 快捷问答插件 · 需求文档

> - 版本：0.2.0（评审修订版，待 §8 决策后定稿）
> - 来源：用户口述需求（2026-11-08）；依 Opus 5.5 独立评审（2026-11-09）修订
> - 范围：单个 DSH 插件，覆盖「快捷对话 → Inbox 沉淀 → 升级为正式任务」全链路，配置与 UI 横切
>
> - 现行版本：docs/PRD.md（本文件）
> - 历史版本：docs/archive/PRD-0.1.0.md（0.1.0 初稿，内容原样保留）
>
> - 标注约定：〔建议〕为文档补充项，非用户原始需求；〔待确认 §8-n〕以 §8 结论为准，本文不预设实现

## 1. 目标与定位

在 DSH 中提供一条不进入正式工作区的轻量问答通道：全局快捷键唤起浮层，以受限工具集完成流式、多模态问答；会话实时沉淀到新增的 Inbox，可检索、可续问，并可携带压缩上下文升级为正式任务。

> - **轻**：浮层问答，不新建工作区/任务，不写入既有工作区历史
> - **受限**：工具白名单仅 Web Search，定位为问答而非 Agent 执行
> - **可演进**：Inbox 会话可携带压缩上下文升级为正式任务
>
> - **非目标**：调用 Web Search 之外的任何工具；替代正式工作区；把快捷对话写入 DSH 工作区

## 2. 术语与边界

| 术语 | 定义 |
| --- | --- |
| 侧栏功能导航区 | DSH 左边栏左上角的功能入口区（插件 / 自动化任务 / 上下文洞察 / 更多），非项目工作区 |
| 工作区 | DSH 中以工作目录为维度的项目空间；其内任务/会话拥有完整工具与权限 |
| 快捷对话框 | 全局置顶的浮层 UI，L1 的对话界面 |
| 快捷对话 / Inbox 会话 | 由快捷对话框发起、仅启用 Web Search 的多轮问答会话；沉淀后称 Inbox 会话 |
| Inbox | 侧栏新增入口及插件自有存储，仅存放本插件会话，与工作区/任务隔离 |
| 正式任务 | 工作区中的任务/会话 |
| 升级 | 将 Inbox 会话（携带完整或压缩上下文）转为正式任务的操作 |
| 视觉模型 | 具备图片理解能力、用于承接带图轮次的模型 |
| 对话 Bing | 原文用语，含义未定，见 §8-1 |

## 3. 需求分层

主链路：快捷键唤起 → 流式问答 → 实时沉淀 Inbox → 检索/续问 → 升级为正式任务。依赖为单向：L2 消费 L1 产物，L3 消费 L2 产物；配置与 UI 横切各层，不构成独立层级。

| 层 | 职责 | 依赖 | 章节 |
| --- | --- | --- | --- |
| L1 快捷对话（核心） | 唤起、输入、受限问答、流式渲染、多轮与会话生命周期 | 入口＝全局快捷键；依赖横切配置 | §4.1 |
| L2 Inbox 沉淀 | 侧栏入口、隔离存储、页面规格、检索、续问 | 消费 L1 的快捷对话 | §4.2 |
| L3 升级为正式任务 | 升级入口、上下文携带、目标工作区与权限 | 消费 L2 的 Inbox 会话 | §4.3 |
| 横切 | 默认/视觉模型、快捷键设置、DSH 原生 UI | 作用于 L1–L3 | §4.4 |

## 4. 功能需求

### 4.1 L1 快捷对话（核心）

- **FR-1.1 全局唤起**：全局快捷键（macOS 默认 `Option + Space`〔待确认 §8-10〕）在桌面端壳运行、任意界面与焦点下唤起浮层；适用前提与形态差异见 §4.5，已知冲突风险见 §5；收起与冲突提示〔建议〕。
- **FR-1.2 提问输入**：支持键盘文本或语音输入；语音转写文本可编辑后发送〔建议〕；ASR 方案与授权时机〔待确认 §8-8〕。
- **FR-1.3 图片与视觉**：图片以多模态消息体随轮次提交，不经任何工具读取；承接模型需具备视觉理解能力，不足时的路由见 FR-4.2；图片规格〔待确认 §8-9〕。
- **FR-1.4 能力约束**：复用 DSH harness，工具白名单**仅 Web Search（web_search）**；创建会话时只注入该工具定义，执行层拒绝其余调用，前端不暴露其他工具入口；明确禁用内置工具、skills、subagent/workflow、MCP、定时任务与 goal；是否检索由模型按需决定，不强制每轮联网；检索结果中诱导调用其他工具的内容一律无效。
- **FR-1.5 输出与渲染**：流式返回，实时渲染 Markdown / LaTeX 数学公式〔待确认 §8-6〕；Web Search 来源展示形式〔待确认 §8-11〕〔建议〕。
- **FR-1.6 布局**：初始为紧凑输入态；有回答返回时纵向平滑扩展以容纳更多内容〔建议：超出上限后内部滚动〕。
- **FR-1.7 多轮与生命周期**：同一浮层内连续追问，上下文仅在该快捷对话内有效；会话**实时持久化**（非关闭时写入），崩溃/强退不丢已生成内容；同一时刻仅一个浮层会话；唤起时新建/恢复与流式期间收起浮层的生成行为〔待确认 §8-5〕；浮层内提供「新对话」〔建议〕。
- **FR-1.8 键盘与操作**〔建议〕：`Enter` 发送 / `Shift+Enter` 换行、`Esc` 收起、停止生成、复制、重新生成、浮层内升级入口；唤起后焦点自动落输入框，浮层出现在当前活动屏幕。

### 4.2 L2 Inbox 沉淀

- **FR-2.1 侧栏入口**：在侧栏功能导航区（现有「插件 / 自动化任务 / 上下文洞察 / 更多」）新增一个入口项（原文称「inbox」），与四项同级；命名大小写/中文化〔待确认 §8-7〕。
- **FR-2.2 隔离与存储**：快捷对话历史只写入 Inbox，不落入任何 DSH 工作区或任务列表；由插件自有存储承载，会话不绑定项目 cwd（实现前提见 §4.5）；实时持久化。
- **FR-2.3 Inbox 页面规格**：列表 + 详情布局；列表项含自动标题、首问摘要、时间、模型、含图标记、已升级标记〔建议〕，默认按最近更新倒序；空态；标题生成规则〔待确认 §8-13〕。
- **FR-2.4 检索**：按时间、关键词检索历史会话，覆盖问题与回答内容〔建议〕。
- **FR-2.5 续问**：打开历史会话可继续问答，上下文（含图片与引用）完整保留；续问位置〔待确认 §8-5〕。
- **FR-2.6 进入「对话 Bing」**〔待确认 §8-1〕：原文「从 Inbox 选项进入到对话 Bing」含义未定，本文不预设实现；候选见 §8-1。
- **FR-2.7 管理**〔建议〕：删除单条会话与清空 Inbox；删除已升级会话不影响已创建的正式任务。

### 4.3 L3 升级为正式任务

- **FR-3.1 升级入口**：浮层内与 Inbox 内均可发起升级，回应原文「将此对话升级」。
- **FR-3.2 上下文携带**：默认以压缩上下文作为新任务初始输入（压缩优先复用 DSH 原生能力，见 §4.5）；是否另提供「原样升级」〔待确认 §8-2〕；携带范围（图片、Web Search 引用、模型设定）及超出目标上下文窗口的处理〔待确认 §8-2〕。
- **FR-3.3 目标工作区与权限**：按 DSH 新建任务流程，由用户指定目标工作区（工作目录）及权限相关配置；是否允许新建工作区、以及原文「工作区域或权限」是二选一还是并列〔待确认 §8-3〕；确认后创建正式任务并跳转，任务从工作区侧（Inbox 之外）进入并常驻。
- **FR-3.4 升级后**：正式任务使用 DSH 完整工具集，不再受 Web Search 白名单限制〔建议〕；Inbox 原会话处理与是否允许重复升级〔待确认 §8-4〕。

### 4.4 横切配置与 UI

- **FR-4.1 默认模型**：插件管理页提供「默认调用模型」设置，选项取 DSH 当前可用模型〔待确认 §8-12 具体列表〕；未设置时回退 DSH 默认模型；对新会话即时生效、进行中会话沿用发起时模型〔建议〕；会话内临时切换〔待确认 §8-12〕。
- **FR-4.2 视觉模型兜底**：插件管理页另设「视觉模型」〔建议〕；带图轮次自动路由到视觉模型，或先由视觉模型生成图片描述再交默认模型；仅当无任何可用视觉模型时才禁用图片输入，避免原始需求 2 落空。
- **FR-4.3 快捷键设置**：快捷键自定义项位于插件管理页，与 FR-1.1 联动生效〔建议〕。
- **FR-4.4 原生 UI**：侧栏入口、快捷对话框、Inbox、升级流程、配置页统一使用 DSH 原生组件、主题 token、间距与动效；浮层在 DSH 主窗口外仍保持原生风格，不引入独立视觉体系。

### 4.5 平台依赖与可行性（前置确认项）

| 依赖 | 需向 DSH 确认的能力 | 若不支持的风险 / 降级 |
| --- | --- | --- |
| 侧栏入口 | 插件能否注册侧栏一级导航项 | 降级为「更多」内的二级入口 |
| 全局唤起 | 能否注册系统级全局快捷键与独立置顶窗口；桌面端与 Web GUI 差异 | 纯 Web 形态无法做到系统级全局，需限定桌面端 |
| 隔离会话 | 能否创建不绑定工作区/cwd、且仅注入白名单工具的 harness 会话 | FR-2.2 / FR-1.4 无法实现，需重定义存储与执行环境 |
| 上下文压缩 | 能否复用 DSH 原生压缩能力 | 插件自行摘要，需在 §8-2 明确策略 |
| 创建任务 | 能否按指定工作目录与权限模式创建任务并跳转 | FR-3.3 降级为手动创建 |
| 配置承载 | 插件管理页能否承载插件自有设置项 | FR-4.1/4.2/4.3 需另设入口 |

## 5. 全局约束

- **安全**：白名单为硬约束，落在 harness 层（只注入 web_search 定义 + 执行层拒绝），前端仅不暴露其他工具入口；细则见 FR-1.4。
- **性能**：流式输出与实时渲染不得阻塞输入；唤起至可输入、首字延迟的判据见 §6。
- **隐私与数据**：语音、图片与 Web Search 查询是否落盘、保存位置与保留期〔待确认 §8-14〕；Inbox 数据是否计入 DSH 备份〔待确认 §8-14〕；Web Search 调用给出成本/配额提示。
- **兼容性与已知风险**：`Option + Space` 在 macOS 部分应用会输入不换行空格，且常被 ChatGPT 桌面版、Raycast 等占用；系统级全局快捷键与独立置顶窗口依赖桌面端壳，Web GUI/CLI 形态下的行为见 §4.5；多显示器下浮层出现在当前活动屏幕。
- **优先级与 MVP**：P0＝文本输入、流式 Markdown/LaTeX、仅 Web Search、Inbox 列表/检索/续问、压缩升级、视觉模型兜底；P1＝语音、图片输入、快捷键自定义、异常与边界、导出；P2＝会话内切换模型、主题与多显示器细节。逐条标签见 §6。

## 7. 异常与边界

| 场景 | 预期行为 | 关联 FR |
| --- | --- | --- |
| 断网 / Web Search 超时、无结果、引用失效 | 可降级为不检索并提示；不阻塞流式输出 | FR-1.4, FR-1.5 |
| 模型报错或限流 | 保留已生成内容，可重试 / 重新生成 | FR-1.5, FR-1.8 |
| 流式中断 | 已生成内容保留且已沉淀，可重试续写 | FR-1.7 |
| 流式过程中收起浮层 | 按 §8-5 结论处理 | FR-1.7 |
| 麦克风被拒 / ASR 失败 | 回退键盘输入，不丢已输入内容 | FR-1.2 |
| 图片格式 / 大小 / 数量超限 | 明确提示，不影响文本轮次 | FR-1.3 |
| 多轮超出上下文窗口 | 自动压缩或提示升级为正式任务 | FR-1.7, FR-3.2 |
| DSH 后台未运行 / Web 标签页关闭时按快捷键 | 不唤起且无残留浮层，形态差异见 §4.5 | FR-1.1 |
| 升级时目标工作区不存在或无权限 | 阻止创建并提示重新选择 | FR-3.3 |
| 检索结果诱导调用白名单外工具 | 服务端拒绝，对话中不出现工具执行 | FR-1.4 |
