# dsh-friday · 项目启动记录

> - 日期：2026-11-09
> - 版本：0.1.0（产品首个可运行版本的目标版本）
> - 需求基线：[归档 PRD](../archive/PRD-0.3.0.md)（0.3.0，定稿版）
> - 源码隔离目录：`deepseek-v4.1 flash/`
> - 目的：让不同模型在各自目录内独立开发同一产品，避免源码、构建产物与依赖互相污染

## 1. 用户目标

> - 交付一个带左侧栏入口的 DSH 插件，包名 `dsh-friday`。
> - 功能范围以 [归档 PRD](../archive/PRD-0.3.0.md) 0.3.0 为准：快捷浮层问答 → Inbox 沉淀 → 压缩升级为正式任务。
> - 源码放入新建的 `deepseek-v4.1 flash/` 文件夹隔离。
> - 按正常产品开发流程保留过程文件、技术选型说明、子代理调用记录与测试记录。

## 2. 交付物清单

> - 可安装的 DSH bundle：`deepseek-v4.1 flash/`
> - 插件源码、构建脚本、图标、locale、README
> - 过程文档：启动、技术选型、架构、计划、子代理日志、测试计划与报告、发布说明
> - 安装与验证记录：本机 profile 实装、侧栏入口、浮层、Inbox、升级流程的可复现步骤

## 3. 产品边界（本版本）

> - 仅 macOS 桌面端 Web GUI 内的全局快捷键（页面级），系统级全局热键受 DSH 桌面壳能力限制，作为已知限制记录。
> - 工具白名单仅 `web_search`；执行层同时用 guard 兜底。
> - 本版本不实现语音、Windows/Linux 映射、LaTeX、会话内切换模型、导出。
> - Inbox 会话使用 DSH 原生 Session 存储与标题服务；插件只保存派生元数据（归档标记、升级关联、图片摘要缓存）。

## 4. 工作方式

> - 先做最小可安装骨架，验证侧栏与浮层挂载，再逐层实现 L1 → L2 → L3。
> - 每完成一个阶段更新过程文档与测试记录。
> - 高难度设计/评审交给高能模型；界面审美交给审美能力更强的模型；低难度重复工作不占用高能模型。
> - 所有子代理调用串行执行，不做并发；调用原因、模型、输入范围与结论写入 `03-model-and-subagent-log.md`。
