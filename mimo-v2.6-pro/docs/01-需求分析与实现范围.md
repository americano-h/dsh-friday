# 01 · 需求分析与实现范围

> - 需求基线：[归档 PRD](../../docs/archive/PRD-0.3.0.md)（0.3.0 定稿版，14 项决策已落地）
> - 本文是实现前的需求解读与范围裁剪，验收口径以 PRD §6 为准，不在此重复
> - 标注约定：〔平台限制〕＝平台能力不支持、按 PRD §4.5 降级或延期；〔实现裁剪〕＝本次实现范围调整

## 1. 需求本质

PRD 的核心是一条**不进入正式工作区的轻量问答通道**：

> - 形态：全局快捷键唤起浮层 → 受限问答（仅 Web Search）→ 流式多轮
> - 沉淀：会话实时写入新增的侧栏 **Inbox**（隔离存储、可检索、可续问）
> - 演进：Inbox 会话可压缩上下文**升级为正式任务**（工作区选择、原会话归档）
> - 横切：默认/视觉模型、快捷键、30 天保留期、全界面 DSH 原生风格

## 2. 需求分层与依赖

> - L1 快捷对话（§4.1）：核心链路，产出 Inbox 会话；依赖横切配置
> - L2 Inbox 沉淀（§4.2）：消费 L1 产物；侧栏入口、检索、续问、查找窗口、管理
> - L3 升级（§4.3）：消费 L2 会话；压缩、工作区选择、归档态
> - 横切（§4.4）：模型、快捷键、保留期、原生 UI，作用于 L1–L3

## 4. 范围外与延期（与 PRD 对齐）

> - 〔延期〕语音输入、Windows/Linux 快捷键映射、LaTeX 渲染、会话内切换模型、导出
> - 〔平台限制〕系统级全局快捷键与独立置顶窗口（见 docs/03 §2）：本实现提供应用内快捷键唤起浮层
> - 〔实现裁剪〕快捷键的绑定编辑走 DSH 原生快捷键设置页，插件管理页展示并跳转

## 5. 关键非功能约束

> - 安全：白名单硬约束在 harness 层（restrict + guard），前端仅不暴露入口
> - 性能：流式渲染不阻塞输入；唤起可输入 < 300 ms（浮层常驻挂载、仅切换可见性）
> - 隐私：图片与检索查询随会话日志按 DSH 机制存储与备份；无语音数据
> - 兼容：仅 macOS 桌面端为验收目标；Web GUI 下快捷键用 Web 允许的替代组合
