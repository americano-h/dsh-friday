# 03 · 平台可行性评估（PRD §4.5 逐条确认）

> - 方法：`cordis_inspect` 服务/事件目录 + 槽位契约（`dsh-cordis-client-runner` 槽位文档）+
>   官方参考（`dsh-creation-recommendations`）+ 已安装成熟插件源码（dsh-better-sidebar、
>   官方 client-ui-* 包）交叉验证
> - 结论标记：✅ 原生支持 ／ ⚠️ 降级满足 ／ ❌ 不支持（按 PRD §4.5 的降级路径处置）
> - 勘察时间：2026-11-09；目标版本：DeepSeek Harness 桌面端（Web GUI 同源装载）

## 1. 侧栏入口（PRD：插件能否注册侧栏一级导航项）✅

> - 证据：`sidebar.panellist`（root 域 list 插槽，注册项 `{id, order, label}`，图标组件获 `{size, active}`）
>   与 `main`（root 域 keyed 插槽，key＝入口 id）构成「入口 + 主面板」官方配对；
>   官方 `client-ui-plugin-manager`（插件页）、`client-ui-schedule`（自动化任务）即此模式
> - 用法：入口与主面板同用 id `friday-inbox`，经 `ctx.slots.inject` 注册、随插件卸载释放
> - 附注：`ctx.layout.selectPanel(id)` 编程式切换；`ctx.layout.panelInfo` 观测选中态
> - 结论：Inbox 与既有四项同级（order 排在自动化任务之后），满足 FR-2.1

## 2. 全局唤起（PRD：macOS 系统级全局快捷键 + 独立置顶窗口）❌ → ⚠️ 降级

> - 证据：Host/Client 全服务目录中**无**系统级快捷键/全局窗口 API；桌面壳（`dsh-desktop-host`）
>   未向插件暴露 `globalShortcut` 类能力；`ctx.shortcuts` 仅为**应用内**快捷键
>   （README 明确「Customize application keyboard commands for each device」，Web 端还有组合白名单）
> - 降级方案（按 PRD §4.5「纯 Web 形态无法做到系统级全局」的预告）：
>   - 浮层挂在 `shell.overlay`（框架级浮层），由应用内快捷键唤起；macOS 桌面端默认绑定
>     `Alt+Space`（`desktop:macos`），Web 端用平台允许组合（`⌘⇧Space` / `Ctrl⇧Space`）
>   - 收起不销毁（常驻挂载），唤起至可输入 < 300 ms；冲突时用户可在 DSH 原生快捷键设置改绑
> - 遗留风险：`Alt+Space` 在部分 macOS 应用输入不换行空格、可能被 Raycast/ChatGPT 占用——
>   原生快捷键设置有冲突检测与改绑路径，风险可控
> - 结论：FR-1.1 以「应用内快捷键 + 浮层」满足，系统级唤起标记为平台限制（验收时按降级口径）

## 3. 隔离会话（PRD：不归属工作区、但纳入 DSH 会话管理的会话）✅

> - 证据：`sessionController.create({ workspaceId?… })` 的 `workspaceId` 可选；`ctx.sessions.create()`
>   + `ctx.agents.create()` 可建无工作区绑定的会话；会话日志由 `sessionPersistence` 统一持久化，
>   标题由 `sessionTitle` 生成、检索由 `sessionQuery` 承担——「纳入 DSH 会话管理」成立
> - 结论：Inbox 会话不进任何工作区/任务列表，数据管理与备份与 DSH 会话一致（FR-2.2）

## 4. 上下文压缩（PRD：能否复用 DSH 原生压缩）✅

> - 证据：`compaction` 服务（`compactRegion(start, end, {session, options})` → `CompactionResult`
>   含 `summary: ContentBlock[]` 与阴影区间）；`dsh-compaction-basic` 为已装配实现
> - 用法：升级时对该 Inbox 会话全区间压缩，`summary` 作为新任务初始输入
> - 降级：服务缺失/失败时以默认模型自写摘要提示词兜底（结果仍标注「压缩上下文」）
> - 结论：FR-3.2 满足

## 5. 创建任务（PRD：列工作区、复用新建流程、按所选创建并跳转）✅

> - 证据：`workspaceRegistry.list()`（含 `attachSession`）、`workspaceController.create`（Remote）、
>   Client 侧 `uiWorkspace.pickDirectory/startSession/openSession`、`workspaces.create`
> - 用法：升级弹窗列出全部工作区（`workspaceRegistry.list()`）＋「新建工作区」按钮
>   （`uiWorkspace.pickDirectory` + `workspaces.create` 原生流程，权限配置不另设）；
>   确认后建新会话、`attachSession` 挂入、`uiWorkspace.openSession` 跳转
> - 结论：FR-3.3 满足；目标不存在/无权限时阻止并提示（§7 边界）

## 6. 配置承载（PRD：插件管理页承载四类设置）✅

> - 证据：`plugins.bundle.config`（keyed 插槽，键＝bundle 包名，渲染于 bundle 详情页）为官方
>   配置区插槽（voice-input-bundle 即此模式）；`sessionController.modelCatalog()` 提供可选模型目录
> - 用法：配置页承载默认模型、视觉模型、快捷键（展示 + 跳转原生设置）、保留期；
>   读写走插件私有 API，持久化于 `<profileHome>/plugin-data/dsh-friday/`
> - 结论：FR-4.1/4.2/4.3/4.5 满足

## 7. 归档态（PRD：Inbox 会话转归档、不出活动列表、阻止重复升级）✅

> - 证据：DSH 的会话归档（`workspaceRegistry.archiveSession`）面向工作区会话；Inbox 会话无工作区，
>   故由**插件元数据**承载：`status: 'active' | 'archived' | 'deleted'`，服务端拒绝重复升级
> - 结论：FR-3.4 满足（归档态语义由插件元数据模拟，符合 §4.5 的预期处置「以标记位模拟」）

## 8. 删除语义补充说明（FR-2.7）

> - DSH 会话日志为追加式（`sessionPersistence` 无删除 API），会话管理本身是「归档/隐藏」语义
> - 本实现「删除/清空/到期清理」＝ 置 `deleted`/`archived` 标记并移出 Inbox 活动列表，
>   日志文件随 DSH 会话管理与备份策略走（与 FR-2.2「统一复用 DSH 会话管理机制」一致）
> - 验收口径相应取「不可见、不可再升级、可检索性从 Inbox 移除」
