## 里程碑

| 里程碑 | 目标 | 判定 |
| --- | --- | --- |
| M0 需求与可行性 | 逐条确认 PRD §4.5 的 7 项平台依赖是否成立 | 侦察报告落盘并给出降级策略 |
| M1 技术评审 | 架构与前端审美分别由高能模型独立评审 | 评审意见进入选型与实现 |
| M2 可运行插件 | 「侧栏 Inbox 一级入口 + 主面板 + 浮层 + 配置页」安装后可见 | `dsh --profile web --dump-config` 出现唯一行；浏览器实测侧栏出现 Inbox | 达成 |
| M3 主链路 | 提问 → 流式回答 → 沉淀 → 检索/续问 → 升级 | 端到端冒烟脚本通过 | 达成（23/23） |
| M4 交付 | 验收对照、限制说明、变更记录齐备 | 文件齐全 | 达成 |

## 质量原则

> - **先跑通再美化**：先交付安装可见的最小骨架，再补视觉与交互细节；不做预览 HTML、mock 壳、截图脚本。
> - **以实际运行为准**：web profile 下依据 `dsh --profile web --dump-config` 的组合结果、boot payload 模块图、HTTP `health` 与浏览器实测判断生效，不依据日志或进程列表推断。
> - **不掩盖降级**：所有相对 PRD 的偏差必须写入 `08-已知限制与后续版本计划.md`，不在交付报告中含糊带过。
> - **串行评审**：子代理调用按用户要求串行进行，不为提速并发。
