## 实施顺序（串行，符合用户「不追求速度」）

> - 先骨架后细节：先保证 `install_bundle` 后侧栏入口与主面板可见，再补问答与升级。
> - 先 Host 后 Client：接口契约固定后再写 UI，避免两侧反复对齐。
> - 每一处 Slot 组件包 ErrorBoundary，注册动作包 try/catch，避免单个组件抛错拖垮整页。

## 风险登记（来自评审）

| 风险 | 缓解 |
| --- | --- |
| 模块/插槽注册失败 | panellist 的 `id` 与 main 的 `key` 统一常量；注册 try/catch；ErrorBoundary |
| `llm.stream` 首次不可用 | `health` action 暴露 provider/adapter 状态；错误原文回显 UI；模型目录校验默认路由 |
| `Option+Space` 输入不换行空格 | capture 阶段判断 `e.code === 'Space' && e.altKey` 并 `preventDefault()` |
| 提示注入经升级进入完整工具会话 | 压缩结果预览 + 用户确认 + 不可信内容标注 |
| 并发写丢更新 | 内存权威 + 单一串行写链 + 防抖 + 关键节点立即落盘 |

## 验收方式

> - 安装结果以 `install_bundle` 的 `application` 为准。
> - Slot 生效以 `cordis_inspect_query` 无参目录 + 已安装资源核对为准；渲染效果以连接页面观察为准并如实报告验证边界。
> - 主链路以 `tests/api-smoke.mjs` 对 HTTP 接口的实测为准。
