# 10 · 测试环境隔离方案

> - 文档版本：0.1.0
> - 触发原因：用户明确要求「这一个版本插件开发完成后不在 desktop 进行测试，而是在 dsh web profile 进行，进行一定的隔离处理」；且 desktop 中已由另一模型安装了 `ds-v4.1-flash` 版构建（用户会先行禁用）。

## 隔离目标

> - 不安装、不启用、不写入 desktop profile 的任何插件行或配置。
> - 不与平行开发的 `dsh-friday` / `ds-v4.1-flash` 构建在包名、路由、Slot id、数据上发生冲突。
> - 测试过程可重放、可撤销，且不影响用户既有 `web` profile 的补丁层。

## 具体隔离措施

| 层 | 措施 | 说明 |
| --- | --- | --- |
| 源码隔离 | 全部源码与过程文件位于 `hy4/` | 与仓库根部需求基线、其他模型目录物理隔离 |
| 包名隔离 | `@local/dsh-friday-hy4`（scoped + `hy4` 后缀） | 与 desktop 中 `dsh-friday` 及平行构建不重名；插件管理页可区分 |
| 路由隔离 | `/plugins/dsh-friday-hy4/api`、`/plugins/dsh-friday-hy4/image` | 同一 profile 内多份构建并存也不会串数据 |
| Slot 隔离 | `sidebar.panellist.id` / `main.key` = `dsh-friday-hy4-inbox`；overlay id = `dsh-friday-hy4-quick`；config key = 包名 | 避免多份构建抢占同一面板 id |
| 数据隔离 | `$DSH_HOME/storages/dsh-friday-hy4/<DSH_PROFILE>/` | web 与 desktop 数据物理分离；实测 `health.dataDir = .../dsh-friday-hy4/web` |
| 配置隔离 | `settings.json` 随数据目录按 profile 存放 | 不写入任何 profile 的 `cordis.patch.yml` |
| 安装隔离 | 仅 `dsh plugin --profile web add <hy4/src>` | 官方 CLI 在 web profile 内建立 link 并登记 bundle；**未调用** `plugin_manager install_bundle`（那个会落到 desktop） |
| 启动隔离 | 独立端口 `51777` + `--no-open` + 托管后台作业 | 不启动替代 GUI、不覆盖当前会话的 Web GUI |
| 身份隔离 | `DSH_PROFILE=web DSH_PROFILE_DIR=.../profiles/web` 显式注入 | 修正了从 desktop 会话继承 `DSH_PROFILE=desktop` 导致的数据目录错写 |
| 补丁层隔离 | 未修改 `web/cordis.patch.yml` | 曾准备 `--patch` overlay，因 CLI 已自动登记 bundle 而取消（避免重复行），并删除该临时文件 |

## 环境事实（用于复核）

> - `~/.dsh/profiles/desktop/package.json` 中存在 `"dsh-friday": "link:/Users/mac/d/dsh-friday/deepseek-v4.1 flash"`（**平行开发产物，本次未改动、未删除、未禁用**）。
> - `~/.dsh/profiles/web/package.json` 本次仅新增一行依赖与一行 `dsh.profile.bundles`：`@local/dsh-friday-hy4`。
> - `dsh --profile web --dump-config` 中 `dsh-friday-hy4` 行恰好出现 1 次。
> - web 启动时有一条既有告警：`better-sidebar (dsh-better-sidebar): pending (waiting for service: webRuntime)`，属该 profile 既有插件，与本插件无关。

## 重放步骤

```bash
# 1) 仅在 web profile 安装
dsh plugin --profile web add /Users/mac/d/dsh-friday/hy4/src

# 2) 用独立端口启动（务必显式指定 profile 环境变量）
DSH_PROFILE=web DSH_PROFILE_DIR=/Users/mac/.dsh/profiles/web \
  dsh --profile web --no-open --host 127.0.0.1 --port 51777

# 3) 从启动输出取 token，跑冒烟
cd /Users/mac/d/dsh-friday/hy4
node tests/api-smoke.mjs http://127.0.0.1:51777 '<token>'
```

## 撤销方式

> - 停止后台作业（本次作业 id `bash-4a04ee6afc2a486e`）。
> - `dsh plugin --profile web remove @local/dsh-friday-hy4`（会同时移除 `dsh.profile.bundles` 中的登记）。
> - 可选：删除 `~/.dsh/storages/dsh-friday-hy4/web/` 测试数据。
> - desktop profile 全程无变更，无需恢复。

## 隔离验证结果

> - `health.profile = web`、`health.dataDir = /Users/mac/.dsh/storages/dsh-friday-hy4/web` → 通过。
> - 冒烟脚本 `profile isolation` 项 → 通过。
> - `~/.dsh/storages/dsh-friday-hy4/` 下仅保留 `web/`（首次误作用域产生的 `desktop/` 空数据已核查内容后清除）。
