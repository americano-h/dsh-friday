# 03 · 技术路线与框架选型

> - 文档版本：0.1.0
> - 决策人：本次开发（Hy4 · WorkBuddy）
> - 原则：技术路线与框架由本次开发自行决定，但必须在过程文件中阐明选择原因

## 总路线

**单 bundle、Host + Client 双半、零构建纯 JavaScript、Cordis 原生扩展点、插件自有持久化、原生主题 token。**

| 维度 | 选择 | 原因 |
| --- | --- | --- |
| 交付形态 | 一个本地 bundle（`@local/dsh-friday-hy4`），同时声明 `dsh.bundle.patch` 与 `dsh.client` | DSH 插件的唯一标准形态；Host 负责数据与模型，Client 负责 UI，职责与运行环境天然分离；单包便于隔离目录整体迁移 |
| Host 运行时 | Node ESM，仅用 `node:*` 内置模块 | 本地链接安装的 bundle 无法稳定解析 `@deepseek-ai/*`；零依赖、零构建脚本可避免 `install_bundle` 的 `pendingBuilds` 与版本豁免风险 |
| Client 运行时 | `window.__ModuleLoader__.load` 工厂 + `require('react')` + `React.createElement`（无 JSX） | 发行包与官方模板一致；无 JSX 就不需要编译工具链；React 由浏览器模块表提供，避免重复安装 |
| UI 扩展点 | `sidebar.panellist` / `main` / `shell.overlay` / `plugins.bundle.config` 四个 Slot | 源码确认这四个 Slot 的注册项与渲染契约；不替换任何 `replaceRisk: shadows-shipped-ui` 的既有 seat |
| 样式 | 组件内 `<style>` React 元素 + 仅 `--dsw-alias-*` token，明暗通过 `color-mix(in srgb, var(--a) N%, var(--b))` | 主题切换自动生效；不引入 `dsh-client-ui-primitives`（官方 practices 明确禁止普通 JS 插件加载该包） |
| Client↔Host 通信 | 单条 `webServer` exact 路由 + `fetch` POST JSON（action 分派） | `dsh-chat-manager` 已验证的生产范式；避免依赖 `ctx.remote` 自定义命名空间或 Typert 生成清单（后者需构建产物） |
| 请求准入 | `ctx.connection.requestRejection(req)` | 与官方桌面端转发请求一致；不做仅靠同源判断的弱校验 |
| 存储 | `$DSH_HOME/storages/dsh-friday-hy4/<profile>/` 下 `inbox.json` + `settings.json` + `images/`，原子写（temp + rename）+ 串行写链 + 500ms 防抖 | 无需 zod/schemastery 即可实现；与 DSH 存储目录约定一致；评审意见要求「内存为唯一权威、单一写入方」以避免读-改-写丢更新 |
| 流式 | Host 增量累积到内存消息 → Client 150ms 轮询带 cursor 的增量 | `host.call` 无流式能力（Promise JSON RPC），而 `llm.stream` 是 Host 侧异步迭代器；轮询是零构建下唯一稳妥的近流式通道 |
| 模型调用 | `ctx.llm.stream` + `tools:[web_search]` + Host 工具派发白名单 | 复用 DSH harness 的 provider 抽象与凭证；不自行拼 HTTP 请求；工具定义在请求层只注入一个 |
| 检索 | `ctx.web.search`（执行层唯一允许的工具） | 与 PRD「仅 Web Search」一致；结果按不可信数据处理，不抓取 URL |
| 上下文压缩 | 单轮 LLM 摘要 + 确定性兜底 | `ctx.compaction` 需要 Agent 上下文，插件无法复用；PRD §4.5 要求不支持时明示算法 |
| 配置 | 自定义 `plugins.bundle.config` 页 + `settings.json` | 零构建本地 bundle 无法可靠 import `@deepseek-ai/schemastery`；自定义页可承载四类异构设置的联动校验 |
| 版本 | 0.1.0 | 首个可运行里程碑；遵循项目 `x.y.z` 规则 |

## 被否决的备选方案

| 备选 | 否决原因 |
| --- | --- |
| TypeScript + tsdown 构建 | 需要构建脚本与 devDependencies；`install_bundle` 会触发 install script 审批，且本地目录链接安装不跑构建，产物无法保证存在 |
| 复用真实 DSH Session 作为 Inbox 会话 | 能获得原生流式/压缩/备份，但插件无法把「不属于任何工作区」与「纳入 DSH 会话管理与备份」同时满足；且会给工作区侧带来零新增记录的风险（PRD FR-2.2 要求零新增） |
| `export const Config` + settings 服务自动表单 | 需要 `@deepseek-ai/schemastery`（评审 P1 亦认可自定义配置页为 v0.1.0 可接受方案） |
| iframe 承载页面 | 官方 practices 明确禁止：iframe 不继承主题 token、明暗切换与 `ctx.locale` |
| 每 token 落盘 | 评审 P0：O(n²) 写入量且易与删除/清理产生读-改-写竞态 |
| 每个 delta 直接推给 Client（SSE/WebSocket） | 需额外路由与流生命周期管理，零构建下收益低于风险；轮询已满足 PRD 的「流式渲染不阻塞输入」 |

## 评审意见的采纳

> - **架构评审（Opus 5.5）**：内存权威 + 500ms 防抖 + 关键节点立即落盘；消息带 `status` 并在启动时把残留 `streaming` 标为 `interrupted`；工具调用按 `index` 聚合、最多 3 轮、最后一轮不传 tools；白名单放在 Host 派发函数；`requestId` 幂等；升级前预览压缩结果；`e.code === 'Space' && altKey` 处理 macOS 不换行空格。
> - **前端评审（Kimi K3.1 Pro）**：4px 网格（4/8/12/16/20/24）、圆角 6/8/12px、13px/20px 正文、12px/18px 辅助、40px 行高；双栏 288–320px + 1px `border-l1` 分隔；浮层 560px、180–220ms 动画、`bg-overlay` + `border-l2`；侧栏 glyph 用 `currentColor` + active 品牌色；`color-mix` 两端都用 token。
> - 详见 `05-子代理调用与模型选型记录.md`。
